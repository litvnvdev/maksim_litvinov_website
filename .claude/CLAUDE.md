# Правила работы над этим репозиторием

## Процесс внесения изменений

1. Перед любым изменением кода сформулируй намерение одним абзацем:
   что меняем, в каком файле, зачем.
2. Покажи текущий код и предлагаемый вариант. Дождись явного
   подтверждения. «Продолжай» без ответа на вопрос — не подтверждение.
3. Одно подтверждение = одно изменение. Не переноси согласие
   на следующие правки.
4. Не трогай файлы, о которых не договаривались, даже если видишь
   в них проблему. Вместо этого скажи о ней отдельно.

## Ветки и коммиты

- Никогда не коммить напрямую в `main`.
- Любое изменение больше опечатки — отдельная ветка:
  `fix/…`, `feat/…`, `refactor/…`, `chore/…`
- Коммиты по Conventional Commits, на английском, повелительное
  наклонение: `fix(portfolio): trap focus inside project modal`
- `git push` и создание PR — только после отдельного явного
  подтверждения на само действие push.

## Технический контекст

- Vite + React 18 + TypeScript, styled-components
- Строгий TS, `any` запрещён
- Перед тем как предложить изменение готовым, прогони
  `npm run build` и `npm run lint`
- Заявлен WCAG 2.1 AA: у интерактивных элементов проверяй фокус,
  клавиатурную навигацию и aria-атрибуты
